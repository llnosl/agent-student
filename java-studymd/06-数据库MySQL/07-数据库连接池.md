# 第六章：数据库 MySQL

## 7. 数据库连接池

## 1. 什么是连接池

数据库连接池是负责**创建、分配、管理和回收数据库连接（`Connection`）**的组件。其标准接口是 `javax.sql.DataSource`。

```text
应用请求连接 → 连接池借出空闲 Connection → 执行 SQL → close() 归还连接池
```

不使用连接池时，每次访问数据库都要建立网络连接、认证并创建会话；这些操作开销较大。连接池会预先维护一定数量的可复用连接。

## 2. 核心优势

- **资源复用**：执行结束后，连接通常返回池中，而不是立即断开数据库连接。
- **提高响应速度**：减少反复建立连接的时间。
- **统一管理**：限制最大连接数，避免应用创建过多连接压垮数据库。
- **健康检查与回收**：验证连接可用性，并回收空闲过久或寿命过长的连接，降低连接泄漏和失效连接带来的风险。

> 重要：使用连接池后仍要关闭 `Connection`。`connection.close()` 的语义变为“归还连接池”，而非一定物理断开连接；不关闭仍会耗尽连接池。

## 3. 常见产品

| 产品 | 说明 |
| --- | --- |
| HikariCP | Spring Boot 默认连接池，轻量且性能好 |
| Druid | 常用于国内项目，提供监控等功能 |
| DBCP | Apache Commons 提供的连接池 |
| C3P0 | 较早期的连接池方案 |

Spring Boot 引入 JDBC、MyBatis 等 Starter 后，通常会自动配置 `DataSource`，默认使用 HikariCP（前提是类路径中可用）。

## 4. Spring Boot 配置示例

```properties
# 基本数据源配置
spring.datasource.url=jdbc:mysql://localhost:3306/study?serverTimezone=Asia/Shanghai
spring.datasource.username=root
spring.datasource.password=你的数据库密码

# HikariCP 连接池配置（按实际并发与数据库容量调整）
spring.datasource.hikari.maximum-pool-size=10
spring.datasource.hikari.minimum-idle=2
spring.datasource.hikari.connection-timeout=30000
spring.datasource.hikari.idle-timeout=600000
spring.datasource.hikari.max-lifetime=1800000
```

| 配置 | 含义 |
| --- | --- |
| `maximum-pool-size` | 池中允许的最大连接数；池满后新请求需要等待 |
| `minimum-idle` | 尽量维持的最小空闲连接数 |
| `connection-timeout` | 获取连接的最长等待时间，超时会抛异常 |
| `idle-timeout` | 空闲连接可被回收前的最长空闲时间 |
| `max-lifetime` | 单个连接在池中的最长存活时间，用于定期替换连接 |

## 5. JDBC 中从连接池获取连接

应用代码面向 `DataSource` 编程：

```java
@Autowired
private DataSource dataSource;

public void queryUser() throws SQLException {
    String sql = "SELECT username FROM user WHERE id = ?";

    try (Connection connection = dataSource.getConnection();
         PreparedStatement ps = connection.prepareStatement(sql)) {
        ps.setInt(1, 1);
        try (ResultSet rs = ps.executeQuery()) {
            // 处理结果
        }
    } // connection.close()：归还连接池
}
```

MyBatis、`JdbcTemplate` 等框架也会使用 Spring 管理的数据源，通常不需要在业务代码中手动获取连接。

## 6. 使用注意

1. 连接池大小不是越大越好，应结合并发量、SQL 耗时和数据库最大连接数评估。
2. 始终使用 `try-with-resources` 或框架事务机制及时释放资源。
3. 不要把数据库密码写入 Git；使用环境变量、配置中心或密钥管理服务。
4. 连接池解决的是**连接复用与管理**，不能替代慢 SQL 优化、索引设计和事务设计。

> 记忆：连接池是 `DataSource` 的实现；借连接提高速度，关连接是归还，不关连接会造成池耗尽。
