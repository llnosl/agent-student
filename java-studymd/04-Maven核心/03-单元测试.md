# 第四章：Maven 核心

## 3. 单元测试

### 什么是单元测试

单元测试用于验证一个方法或类的最小功能是否符合预期，常用框架是 JUnit。

**使用场景：**修改代码后快速检查旧功能是否被破坏。

### 快速案例

业务代码：

```java
public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }
}
```

测试代码放在 `src/test/java`：

```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

class CalculatorTest {
    @Test
    void add_shouldReturnSum() {
        Calculator calculator = new Calculator();
        assertEquals(5, calculator.add(2, 3));
    }
}
```

运行 `mvn test`：断言成立则通过，否则失败。

### 常用断言

| 断言 | 作用 | 案例 |
| --- | --- | --- |
| `assertEquals(a, b)` | 判断是否相等 | 检查计算结果 |
| `assertTrue(value)` | 判断是否为 `true` | 检查条件 |
| `assertNull(value)` | 判断是否为 `null` | 检查查询无结果 |
| `assertThrows(...)` | 判断是否抛出异常 | 检查非法参数 |

### 常见注解

| 注解 | 作用 |
| --- | --- |
| `@Test` | 标记测试方法 |
| `@BeforeEach` | 每个测试前执行 |
| `@AfterEach` | 每个测试后执行 |
| `@BeforeAll` | 所有测试前执行一次 |
| `@AfterAll` | 所有测试后执行一次 |

**使用场景：**在 `@BeforeEach` 中创建重复使用的测试对象，减少重复代码。

### 依赖范围 scope

`<scope>test</scope>` 表示依赖只在测试代码和测试阶段生效，不会进入正式运行环境。

**案例：**JUnit 只用于测试，因此通常使用 `test` 范围。

> 好的测试应独立、可重复运行，并同时覆盖正常情况和边界情况。
